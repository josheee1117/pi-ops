# ADR-0032: Agent 按异常栈采集有限源码片段

状态为 Accepted，日期为 2026-10-26。诊断只有异常栈时，模型无法区分抛出条件与真实修复方向。中央 Agent 在构建调查上下文前采集 `source.snippet`，Pi Runtime 只接收投影后的证据，不获得文件工具、主机权限或自选路径能力。

## 读取边界

`PI_OPS_SOURCE_ROOTS` 是服务名到绝对目录的 JSON 映射，键必须与 Incident 的 `service` 一致。Agent 跳过 JDK 和常见库帧，取第一个应用帧，按文件名查找，不要求包路径与目录相同。它拒绝路径穿越、根目录外的符号链接和同名文件歧义。根目录应使用只读挂载的源码检出，不应包含生产配置。

读取器优先取出错行上下 80 行内的方法体。方法附近的类注解能放下时一并保留，否则取出错行附近的有限窗口。正文最多 40 行或 1500 字符。密钥赋值在入库前脱敏。证据 id 只依赖 Incident、类、方法和栈行号，不依赖找到后的目录，重试更新同一行。

## 版本与输出边界

找到的方法仍标 `unchecked`，诊断必须写“版本未核对”。找不到服务根目录、文件或存在同名歧义时写 `missing`。窗口没有方法或栈行号超出文件时写 `drifted`，模型不得把该行号当作已确认的缺陷位置。`matched` 预留，本次不生成，也不推断配置当前值。

正文只作为模型输入证据。详情 Markdown、简报 JSON 和运维证据接口去掉 `text`，保留相对路径、行号与版本状态，不公开绝对根目录。源码与 JFR 等关键证据一起优先保留，默认八条证据名额不会挤掉源码。

## 评测与限制

评测与调查调用同一个读取器。DataAsset 使用仓库控制器夹具，栈溢出使用合成 `Recurse.java`，第 7 行对应现有重复栈，版本保持 `unchecked`。没有夹具的标签、SOP 和健康检查案例不获得虚构源码。

真实修复分类要求修复动作引用源码证据 id，并且操作文本包含该片段独有、其他证据没有的事实。该分类是可复算的文本判据，不证明建议可直接发布，也不代替部署版本核对。

赋值扫描不覆盖编码、拼接与注释中的全部秘密。方法窗口不是 Java 编译器，超出窗口或无法识别的声明会保守降为 `drifted`。实际部署必须提供 Agent 可读的源码目录，不能把宿主路径直接当成容器内路径。
